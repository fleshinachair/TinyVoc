# TinyVoice

Schwung `audio_fx` module for Ableton Move: an 11-mode vocal processor (plus the two older PSOLA modes, kept: 13 in the Mode list) on a home page of eight knobs (**VOICE**: Mode, five contextual knobs, Mix, Level) and two more pages (PITCH, MORE), with Freeze (16 s punch-in looper on the input; SPACE knobs 4-5 with its bar length; **no delay or reverb: removed 2026-10-11, the chain has its own**) and Demo (built-in sung phrase that tours the modes; SPACE knob 6).

Module id `tinyvoice`, library `tinyvoice.so`, archive `build/TinyVoice.tar.gz`, include guards `TINYVOICE_*`, widget kinds `custom:tinyvoice_*`. The C prefix is `vt_` / `VT_`.

| # | Mode | Engine | What it is |
|---|---|---|---|
| 0 | Robot | `daft.c` | 16-band vocoder, 4-voice MIDI carrier, drone fallback, formant shift, odd/even stereo, VP-330 ensemble |
| 1 | Snap | PSOLA lead (`modes.c`) | Hard "space-age" Auto-Tune: formant +2.5 st, telephone band with a 2.5 kHz bite; instant at Beauty 0 |
| 2 | Chords | `imogen.c` | 4-voice harmonizer, formant-preserving PSOLA voices, pad-rooted or scale chords (strictly triadic: root, 3rd, 5th, octave) |
| 3 | Prism | 4 PSOLA voices + glass (`modes.c`, `ssb.h`) | 0 ms snap split into 4 harmony lines + tape warmth, then **refraction**: off-grid voice offsets, a Hilbert-shifted L/R pair (non-integer partials) and a modulated comb. Refract (char4) 0 = exactly the old Prism |
| 4 | Tape | delay-line tap (`modes.c`) | Varispeed drop with wow/flutter, dark top, saturation; char4 aliases Tone, char5 = Hiss (tape hiss above 0.5) |
| 5 | Nightcall | `daft.c` (second instance, `daft_set_talker`) | DigiTech-Talker style talkbox: 12-28 % pulse carrier + ~10 % white noise, 250 Hz 4th-order low-cut, 1.2 kHz cavity peak, high shelf, 17.5 % unvoiced breath bleed; pads or drone carry |
| 6 | Scream | PSOLA lead (`modes.c`) | The prank-caller voice changer: -8 st, formant x0.84 (a big throat), a wide band (90 Hz-4.8 kHz) that keeps the chest, clean until Grit is raised; Narrow closes it into a phone line |
| 7 | Dalek | `voice.c` + `ssb.h` | Hilbert-pair single-sideband shifter (+-500 Hz) + 30 Hz ring mod + comb "metal" |
| 8 | HardTune | PSOLA lead (`modes.c`) | Zero-slew quantizer (Key/Scale or a pad), formant preserved, correction depth 0-200 % |
| 9 | Harmony | `voice.c` | 3-tap granular stack (-12, +7, +12 st or the held chord's intervals), pitch-synchronous grain, micro-delays, pans |
| 10 | Walkie | `voice.c` | A handset: 350 Hz-3 kHz 4th-order band + a broad presence peak, a mic compressor (every phrase slammed to the same level), asymmetric diode clip, receiver squelch (burst on open, long tail on close), channel muted between phrases with a faint hiss floor while open |
| 11 | Morph | PSOLA lead (`modes.c`) | Formant-decoupled shift into drive (kept; after the roster) |
| 12 | Double | 3 PSOLA voices (`modes.c`) | Hard-tuned lead + two detuned Haas doubles (15-25 ms) (kept; after the roster) |

The order is the Mode knob's: vocoder/carrier modes (0-5), voice transformers (6-10), then Morph and Double. It is `vt_mode` in `dsp.h`, `k_mode_opts` in `dsp.c`, `MODES` in the generator, `MODES` in `canvas.js` (and the tests' tables). **Indices changed in v1.0** (Robot 0, Snap 1: the old Snap 0 / Robot 1 order is gone); saved states name modes, so they load.

All pitch modes (everything except Dalek, Walkie and the vocoders) share one tracker (`cher.c`: MPM + quantizer + delay line). Dalek and Walkie run no tracker (they `cher_listen`); Harmony runs it only to set its grain length.

Talkbox (the old mode 6) was removed on 2026-10-09, and **Nightcall (2026-10-11) is a new, unrelated engine** (a flagged voicing of the vocoder, not the old formant-filter talkbox). A saved `state` with `"mode":"Talkbox"` loads as the default mode (unknown option rejected, the other keys still restored); a numeric index clamps to the last mode (Double).

## Signal flow (`dsp_process_block_f`)

```
mic (or Demo voice) -> Freeze (record / loop) -> in L/R
in (stereo) - mono -> mode engine -> wet L/R -> Tone -> Spread (ADT chorus; not in the vocoders) --+
in L/R -> dry delay (= engine latency) ---------------------------------------+- Mix -> [headroom] -> Gain -> soft limit -> out
```

- **Mic pre-conditioning**: the input (mic or Demo voice), per channel and before Freeze, goes through a 1-pole high-pass at 120 Hz (`VT_INPUT_HPF_HZ` in `dsp.h`; `y = a(y1 + x - x1)`): engines, gates, AGC, the dry path and Freeze takes all hear it, so pad taps and chassis thumps on the built-in mic don't open the voice gate or fill the vocoder's low bands, and wet/dry stay phase-aligned. 1 kHz within 0.2 dB, 40 Hz ~10 dB down: a 40 Hz thump at -30 dBFS RMS no longer opens Robot (Auto Off, Gate -38), a sung A3 at the same level does (tested). The Space-delay tests feed the filter's inverse so the delay still sees an exact impulse.
- Dry is delayed to the active engine's latency (`fx_latency`, `imogen_latency`, `vox_latency`, `cher_latency`; the vocoders and Walkie 0, Dalek 25 samples = 0.6 ms, Harmony up to 12.1 ms), so wet/dry blends line up. At Mix 100% the dry gain is exactly 0 (`dry_g`). PSOLA modes: ~2-8 ms depending on pitch and formant.
- Output soft limit: transparent below 0.9, eases into 1.0 (Gain reaches +12 dB).
- **Headroom stage** (`headroom()` in `dsp.c`, `TINYVOICE_OUTPUT_HEADROOM` = 0.4955 = -6.1 dBFS in `dsp.h`): for **Nightcall, Scream, Dalek, HardTune, Harmony, Walkie** only (`vt_mode_headroom`), after Spread and before Gain: linear up to 0.8 x the ceiling (-8 dBFS), then eased in (tanh) so the output never reaches it. So at Level 0 dB nothing passes -6.1 dBFS whatever the knobs or the input (tested at extreme settings, with Spread 1); Level is the boost above it. The older modes are not under it (Robot and Snap peak near -2..-6 dBFS as before). Calibrated by the per-engine trims (`DK_TRIM`, `HG_TRIM`, `WK_TRIM`, `HARDTUNE_TRIM`, the talker leveller) so that a voice at Auto's working level lands at about -17..-21 dBFS RMS, peaks -7..-10 dBFS, without the stage doing much.
- **Mode switch** (knob, state or Demo): the running engine's wet fades out over 5 ms (`MODE_FADE_SEC`), the chosen engine takes over at the next block boundary (`run_mode`; a knob swept across several modes lands only on the last) and fades in over 5 ms; the dry path runs straight through. While Robot runs, `cher_listen` keeps the tracker's delay line and analysis window fed (no pitch analysis, ~+0.03 ms), so a switch to a pitch mode reads the live voice instead of audio from before Robot. Measured, cycling every mode on a held note: the largest step after a switch is 0.45-2.2x the steady waveform's (hard cuts were up to 16x, Robot <-> Morph worst); tested at < 3x.
- **The voice gate** (`dsp.c`, input stage): true RMS of the raw input (10 ms, after Freeze/Demo, before any gain) against a fixed threshold, -42 dBFS with Gate at Auto or the Gate's dB level, 50 ms hold. One decision for everything: closed, Robot (`daft_set_voice_present`) outputs exact zeros, polyphonic pad carrier included, and with Auto the input AGC freezes at once and a downward expander takes the input 40 dB down (opens in 2 ms, releases over 60 ms). It sits before the engines and the dry path, after Freeze, so engine tails ring out. A hard input gate at every Gate setting (exact zeros below a manual level) was tried on 2026-10-09 against a reported "bleed" and reverted: the bleed was other tracks' MIDI (see MIDI below), and it cut quiet singing under a manual Gate. History: a peak-riding level (mean |x| x pi/2) read noise ~3 dB hot, so -45 dBFS RMS mic hiss kept opening it with Auto On, the AGC lifted it, and the (since removed) Talkbox played its carrier at ~-20 dBFS from it (seen on the device); an adaptive room-noise threshold missed pauses. Noise above -42 dBFS RMS counts as a voice by definition. The input AGC's boost is capped at +12 dB (it was +24).
- Freeze sits before everything, so the engine and the dry path both hear the loop (pads, carriers and knobs work on it exactly as on a live voice). It is a punch-in looper, `freeze` = Off / Rec / Loop: Rec starts a fresh take at position 0 (the voice is still heard live while recording); Loop (or Off) locks the take at exactly the length recorded; Loop plays it from its start with a 5 ms equal-power crossfade at the wrap (the take's last 5 ms fade into its first, so a loop period is the take minus 5 ms); Off keeps the take, so Off -> Loop replays it; Loop -> Rec replaces it. **Minimum loop (2026-10-12)**: a take is judged when it is stopped (Rec -> Loop / Off): under `FREEZE_REJECT_SEC` (50 ms) it is an accidental tap and is dropped (`loop_len` 0: nothing loops, you stay live); under `FREEZE_MIN_SEC` (120 ms of loop period, so `min_len` = that + the 5 ms crossfade) it keeps recording past the release (`pend` holds the requested state, the voice still heard live) until it is long enough, then locks into Loop or Off; asking for Rec again while it extends clears `pend` (an ordinary take); a take that fills its bar target or the buffer locks as before. The 5 ms equal-power seam stays (inside the 5-10 ms asked for; `FREEZE_XF_SEC` is also the bar-mode timing slack, which is why it was not lengthened). A tap is destructive: the new take overwrote the old one's samples from the first recorded sample (there is no scratch buffer). **Freeze Len** (`freeze_len`: Free, 1 Bar, 2 Bars, 4 Bars; default 2 Bars; saved) sets the take in bars at the host tempo (4 beats a bar, `bars * 240 / bpm * sr`, clamped to the buffer): Rec then stops by itself at exactly that length and loops; it records 5 ms past the target so the wrap crossfade comes out of the extra and the loop period is exactly N bars (no drift against the tempo); stopping early still locks what was recorded; Free waits for you. **Downbeat arming**: in bar mode with Move's transport running, Rec arms (scope freeze field 3; the param still reads Rec) and the take starts on the exact sample of the next downbeat: `plugin.c` passes `host->get_beat_position()` (beats since transport start, < 0 stopped, NULL on old hosts; present on the device) through `dsp_set_transport`, `dsp.c` turns it into samples to the next bar line (4 beats a bar) each block, and `freeze_set_clock` counts it down. A full bar take was recorded 5 ms past the bar line, so its playback starts 5 ms in and the loop's beat 1 stays on the grid (tested within a block). Off or Loop while armed cancels. Transport stopped, or Free: Rec records at once. The host's transport comes from MIDI realtime messages (`shadow_transport_on_realtime`, 24 PPQN), so it needs Move's MIDI clock output on: `midiClockMode` = `output` in `/data/UserData/settings/Settings.json` (it is, on this device). **Freeze banner** (`custom:tinyvoice_freeze`, MORE knobs 3-4, the top row of the 4 x 2 grid, over Freeze and Freeze Len). Its frame is the two cells' graphic area above the host's label band; the host clips text on the right but NOT at the bottom, so text stays on one vertically centred line and everything else is graphics on the bottom rows (a second text line ran into the FREEZE/FRELEN labels, and two strings on one line ran into each other: "FREE2E"). Off: the two values ("Off", "2 Bars") centred in their cells like the stock enum knobs (a custom widget can't hand a cell back to the host's stock drawing). Active: the box is cleared, then ARMED flashes inverted at 4 Hz with "[ *** ARMED *** ]" (or the longest shorter form that fits) and the beats left to bar 1 as squares; REC is inverted "[ REC ]" with a dot and the take filling; LOOP is "[ LOOP 2 BARS ]" with a playhead. The feed's last field is the transport beat (-1 without one). The scope on PITCH still tags ARM / REC / LOOP top right. (The first version only tagged the TUNE scope, which isn't on screen when you turn Freeze on the MORE page, and a module reload keeps the old widget: hence "never shows ARM" on the device.) Filling the 16 s buffer (or reaching the bar count) locks and loops by itself and moves the param to Loop (`freeze_take_full`); transitions fire on a change of the param (`asked`), not on a mismatch with the state, so that self-move isn't read as a new punch-in. Live <-> loop switches fade over 10 ms. 16 s x 48 kHz int16 = 1.5 MB inside `vt_t`.
- Demo replaces the mic with the demo voice, remembers the user's mode and steps through every mode (13) every 4 bars at the host tempo (`dsp_set_bpm`, fed from `host->get_bpm()` in `plugin.c`; 120 until set), holding a virtual Am-F-C-G chord (one per bar) in Robot, Chords, Prism, Nightcall and Harmony (`latch_mode`). **Turning Mode while Demo is on pins the tour on that mode** (any `set_param("mode")` while Demo is active, a state restore included). Switching Demo off restores the user's mode, or keeps the pinned one.
- **Snap's demo** is the same shared phrase as every other mode, played straight through the live engine with no virtual pads, so Key and Scale are heard snapping it (a Snap-only "Believe" phrase with virtual pad presses was tried and removed on 2026-10-09).
- **Demo level**: the demo voice runs through a ~20 ms level normaliser held at `DEMO_LEVEL`, the level Auto steers a real voice to (Auto's peak-riding follower makes that ~6 dB under its nominal 0.25 target), so Snap sounds the same with Auto On or Off (tested within 2 dB, Auto's mean gain within 2 dB of 0).
- MIDI: the chain host calls the FX for every message the slot receives, after MIDI FX, with no channel filter (and a broadcast path), as 3-byte messages; **`dsp_handle_midi` takes only the slot's own MIDI** (2026-10-10). The chain host also *broadcasts every track's MIDI to every audio FX* with source 4 (`MOVE_MIDI_SOURCE_FX_BROADCAST`, `VT_MIDI_SOURCE_BROADCAST`); taken (omni), other tracks' sequencer notes, muted tracks included with their MIDI Out on, played Robot's carrier and Chords/Prism voices (device report: turning the other tracks' MIDI Out off stopped it). Seen on the device with `diag`'s note log: other tracks' notes arrive only as broadcasts on their own channels (0x90/0x91/0x92); every note on the slot's channel (0x93) arrives twice, as source 2 and again as a broadcast. So broadcast channel messages are dropped whole (`plugin.c` passes `source` via `dsp_set_midi_source`, for that one message). `host->slot_recv_channel(inst)` answers **-2 (not slot-registered) for an audio FX instance** on the device (it knows the chain's instance, not its children), so the channel filter it feeds (`dsp_set_midi_channel`; drop other channels when 0-15) is kept for hosts where it works but does nothing here. `diag` ends with `midi ch N` (0 = omni), `foreign M` (dropped), `recv R` (the raw lookup answer) and `last` = the last six note-ons as status/note/source. On this device the slots receive channels 1-4 (`shadow_chain_config.json` `slot_channels` [0,1,2,3]). Not yet confirmed on the device: that a pad pressed on TinyVoice's own track comes as source 2 (or 0), not only as a broadcast. Tested: `test_midi_channel_filter` (Robot/Chords/Prism, Latch Off/On, bit-identical with foreign MIDI; broadcasts ignored on any channel; own pad plays) and `device_smoke.c` through the real ABI and also accepts a 4-byte USB-MIDI packet. Note-ons are counted for the screen. MIDI notes go to 4 voice slots (`dsp.c`). Snap/Morph/Double: newest held note overrides the lead target. Chords/Prism: **one held pad is the chord root**: the same in-key voicing the sung note would get (`vt_chord`: root, 3rd, 5th + octave per the voicing), rooted on the pad and folded near the voice, Auto On or Off (a lone pad voice against the others used to clash); **two or more pads** play exactly the held notes, moved as a block by the octave fold. **Latch** (`latch`, Off/On, MORE knob 6, saved): in Robot, Chords and Prism the pads' chord keeps playing after they are let go. A press with no pad physically held starts a new chord (the old one is replaced at once); presses while others are held add to it, the oldest dropping out past four. Turning Latch On takes the pads held at that moment; Off empties the buffer, which releases the latched voices at once; MIDI all-notes-off (CC 120/123) empties it too. The physical pad state (`voices`) is tracked separately, so lead modes (Snap, Morph, Double, Tape) never latch, and switching to one with Latch On hands the target straight back to the voice. Demo's virtual chord wins over a latch. The scope's pad label shows the newest latched note. Robot: slot i drives carrier voice i, **folded into C3..B4**: held pads keep their names and voicing but move by whole octaves, as a block, until their mean is in C3..B4 (`ROBOT_REG_LO/HI` in `dsp.c`; the last fold holds while the mean stays within 2 st of the range). Move's pads sit around E5 and up, and an unfolded carrier there is above most of the voice's formants: no words, just a high tone (device report, 2026-10-09). E5 plays E4; E5-G5-B5 plays E4-G4-B4; C4 stays C4. With no key held a drone carries the voice, Auto On or Off (with Auto Off it used to be silent, which read on the device as "Robot is too quiet"). The drone is root + fifth + octave of the effective Key (`daft_set_drone_root`), rooted F#2..F3 (C: C3 G3 C4). Scale doesn't change it: every offered scale has the perfect fifth.

## Voice FX (the second personality, 2026-10-12)

One module, two personalities, chosen by the `engine` param (Vocoder, VoiceFX; saved in `state`). **Vocoder is everything above, unchanged** (all 13 modes, four pages). **Voice FX** is pure formant processing of the voice: no vocoder bands, no carrier, no tracker (`cher_listen` keeps it fed). One shared DSP core: one `vt_t`, one calloc in `dsp_init`, nothing allocated while processing (`vfx_t` holds its own `verb_t` tail, ~70 KB inside `vt_t`).

**UI.** `ui_hierarchy` declares `"modes": ["vocoder", "voicefx"]` and `"mode_param": "engine"` (verified in the host's `shared/param_pages/page_plan.mjs`; only minijv used it before, so it is lightly exercised): the host adds its own **Mode** page (a list that writes `engine`; its labels come from the `engine` option names, matched case-insensitively, and `dsp_set_param` accepts any case), and the active mode's level is the walk root. Vocoder shows the Main, Pitch and More pages; Voice FX shows a **Presets** page (the `list_param` / `count_param` / `name_param` triple, `vf_preset` / `vf_preset_count` / `vf_preset_name`, declared on the `voicefx` level only, so the Vocoder has no browser) one page of eight encoders, and a one-knob **Audition** page (Demo; below). Hidden vocoder-side state cannot colour Voice FX: it runs with Auto (input AGC + voice gate) forced on, Tone off, fixed Level, its own Mix, and its own Choir for the stereo chorus, and a test checks the output is **bit-identical** whatever Mode, Key, Gate, Level, Mix, Tone, Spread, Latch and pads are set to. `engine` pulses `is_loading` like a mode change.

**The eight knobs** (own params `vf_*`, defaults = the "Vowel Morph Solo" preset):

| # | Key | Does |
|---|---|---|
| 1 | `vf_vowel` | A E I O U sweep (0 / .25 / .5 / .75 / 1), formant centres interpolated in log frequency |
| 2 | `vf_tract` | formant scale `2^((v-.5) 1.2)`: +-0.6 octave, 0.5 natural |
| 3 | `vf_peak` | formant Q x0.4..x2.5 (x1 at .5) |
| 4 | `vf_choir` | L / R banks detuned apart up to +-7 % per formant (alternating signs), and Choir x 0.7 drives the stereo chorus |
| 5 | `vf_breath` | noise (follows the voice, so silence stays silent) through the formants, plus the voice's own > 3.5 kHz air bled past them |
| 6 | `vf_attack` | onset swell, 0.5 ms .. 120 ms: a slow envelope chases a fast one; their ratio is exactly 1 on a held note |
| 7 | `vf_release` | tail: the formant output through the `verb` FDN, return and RT60 both rise with it (0 = none) |
| 8 | `vf_mix` | **Mix/Drive, two segments**: 0..0.7 is wet/dry (all wet at the knee, with a touch of warmth); 0.7..1 stays all wet while the drive climbs x1.3 -> x5 (level-normalised tanh) |

`vfx.c`: four parallel TPT band-passes (unity at centre) per side, weights falling with the formant; a **wet leveller** holds the bank's RMS at the input's (150 ms, gain 0.25..5x, held in silence), so Vowel, Tract and Peak change tone and not loudness (measured within +-2.5 dB across every knob on the Demo phrase); the headroom stage covers it (`VT_MODE_VOICEFX`, the internal run id one past the Mode knob's 13, so `VT_MODE_COUNT` and its tables are unchanged).

**Demo in Voice FX: the audition phrase.** `demo` (Off / On, the same param the vocoder's More page has) substitutes the input with `groove.c`: a heap-free **eight-bar** electro-funk phrase, so the presets and knobs can be heard with nothing routed in. Dm7 | Dm7 | Bbmaj7 | Cadd9 | Dm7 | Dm7 | Gm7 | A7 over 128 sixteenth steps at the host tempo (`dsp_set_bpm`); two layers: a **bass** (two band-limited saws +-6 ct apart, MIDI 38..60 = D2 and up, so the fundamentals clear the 120 Hz input high-pass; three bass patterns: states, answers, turns around) and four-note **stabs** (staccato, gate 0.3 step, all off the beat, eight saws through one pluck filter and one VCA). Each hit restarts its oscillators and filter, so the loop is exact (`step_len x 128` must be a whole number of samples: 705600 at 120 bpm = 16 s). (Note numbers are C4 = 60, so 38 is D2.) It is injected at the input stage, before Freeze, the input high-pass, the AGC / voice gate, the formant bank and the drive. The vocoder's Demo is unchanged (the sung phrase and the mode tour). The Mode page (`mode_param`) and the Presets browser are drawn by the host, so nothing of ours can sit on them: the `voicefx` level lists a nav entry to an `audition` level holding `demo` alone (`demo` is listed on two pages: the vocoder's More and this one).

**The knobs move during the phrase** (`tour.c`). A timeline over `groove_bar()` (the phrase's position in bars) produces *effective* Vowel, Tract, Peak, Choir and Mix/Drv; `dsp.c` builds an array `vfp[8]` of effective knobs each block (the stored ones, with those five replaced) and hands that to `vfx_set`, the mix and the chorus. **Nothing is written to `vt->p`** (tested: a full loop leaves the knobs and the saved `state` as set; the output with Demo on is bit-identical whatever the five knobs say, while Breath / Attack / Release still matter). Keyframe tables with smoothstep between them, bar 0 = bar 8 on every track so the loop is seamless: bars 1-2 neutral (Peak .15, Mix/Drv .30, vowel A); 3-4 the vowel path u -> o -> a -> e -> i, half a bar each (`vfx_vowel_pair` glides straight between two vowels, not through the ones between on the A E I O U line), Peak .5, Mix/Drv .7 (wet, no drive); 5-6 Mix/Drv .7 -> 1.0 and Peak .5 -> .95 on an "ah"; 7-8 Tract .5 -> .05 (deep chest) -> .95 (soprano) -> .5 and Choir 0 -> 1 -> 0. Because Demo always does this, it cannot preview a preset's Vowel / Tract / Peak / Choir / Mix/Drv (a preset still sets Breath / Attack / Release there); presets are heard with Demo Off.

**On the screen.** While it runs, `get_param` on `vf_vowel`, `vf_tract`, `vf_peak`, `vf_choir` and `vf_mix` answers `disp[]`, a snapshot of the effective values the audio block just used (the vowel shown as a position on the A E I O U line, `(v0 + (v1 - v0) t) / 4`); the host's UI re-reads every visible knob a few times a second, so the OLED shows the knobs turning (there is no push / notify call in the ABI; `disp_on` is cleared the instant Demo or the engine is set, so the next read is the user's own value). `get_param` and `set_param` run on the audio callback thread (plugin_api_v1.h), so the snapshot is race-free and costs a load. `vt->p`, and therefore `state` (what the host saves and hashes, `<prefix>:state`), is never touched: no cache-and-restore is needed, a restart or crash mid-phrase cannot leave animated values in a set, and nothing is ever re-saved because of it (tested: the saved string is identical at every poll through a loop). **A hand on a knob:** a `set_param` of Vowel, Tract, Peak, Choir, Mix/Drv or `vf_preset` while Demo runs and not restoring (the host writes a turned knob from the value it was *showing*, so the player takes over where the dial is) sets Demo to Off, keeps the written value, and every other knob is the user's own again; Breath, Attack and Release are not moved by it, so turning them leaves it running, and a `state` restore is not a hand. Choose a preset *before* starting Demo. Tests: pattern (D minor, every stab note in its bar's chord, every stab off the beat, each bar starts on its root), exact 16 s repeat, bar position, tempo, Demo On bit-identical whatever audio is routed in, every preset under it rhythmic / finite / under the ceiling, the timeline's phases and continuity (4096 steps a bar, no jump), safe with any bar value (NaN, negative, huge), the knobs untouched, `test_voicefx_ghost_hands`. On a Move (`smoke_on_device.sh`, its own instance): presets loudest -15..-21 dBFS, gaps -38..-55 dBFS; the phrase -25..-28 dBFS rms in every bar, peak -6.4 dBFS, **0.11 ms per block**; 196 polls through the ABI see vowel 0..1, tract .05..0.95, peak .15..0.95, choir 0..1, mix/drv .30..1.00.

**Presets** (`presets.c`, static const, each tagged `engine = VT_ENGINE_VOICEFX`; `vt_preset_count(engine)` / `vt_preset_get(engine, i)` filter by tag, the Vocoder has none): Yeah Boy, Robo Talk, Monster Throat (tract -0.35 oct = 0.208), Funky Talkbox, Alien Choir (tract +0.4 oct = 0.833, Choir 1), Vowel Morph Solo. Writing `vf_preset` (transient: never in `state`, so a restore cannot re-apply a preset over saved knobs) loads that preset into the eight knobs. **Not in the engine**: an envelope -> vowel sweep (Yeah Boy's /i/ -> /a/ is Vowel ridden by hand from a start near /i/), so "dynamic" is Attack / Release plus the drive's own level dependence. Tests: every preset under six input kinds stays finite and under the -6.1 dBFS ceiling, a voice lands -32..-10 dBFS, loading a preset never changes what the Vocoder plays (bit-identical).

## Schwung ABI (`move_audio_fx_init_v2`)

Entry symbol exported from `tinyvoice.so`: `audio_fx_api_v2_t *move_audio_fx_init_v2(const host_api_v1_t *host)`.

- Struct `audio_fx_api_v2_t`: `api_version=2`, `create_instance(module_dir, config_json)`, `destroy_instance`, `process_block(inst, int16_t *audio_inout, frames)`, `set_param(inst, key, val)`, `get_param(inst, key, buf, len)` (returns bytes written or -1), `on_midi(inst, msg, len, source)`.
- Audio: **stereo interleaved int16, in place**, 44100 Hz, 128-frame blocks (`dsp_process_block` chunks anything up to any size via `VT_MAX_BLOCK=512` stack buffer).
- Instance-based: Schwung may create several; no globals except the stored `host` pointer in `plugin.c`.
- **Realtime contract**: every entry point runs on the SPI audio callback (~2.3 ms slack per block). After `dsp_init` there is no allocation, locking, I/O, or large stack use. All buffers are fixed-size members of `vt_t`.
- **MIDI needs a second exported symbol**: `void move_audio_fx_on_midi(void *inst, const uint8_t *msg, int len, int source)`. The chain host `dlsym`s it to decide whether an FX gets MIDI at all; the struct's `on_midi` alone is not enough (pads were silently never delivered until this was exported). Every MIDI-handling FX on the device exports it (`ducker`, `capicola`, `magneto`, `trance-gate`); `module.json` flags are not what enables it. `build.sh` and `smoke_on_device.sh` both check for it.
- `on_midi` in the struct should still be non-NULL.
- `get_param` keys beyond the params: `state` (JSON snapshot), `viz` (UI feed), `scope` (widget feed), `diag` (live levels for checking a real mic: input 10 ms RMS max and floor over ~1 s, after the input high-pass, voice gate and Robot gate open share, Robot AGC / leveller, output RMS max, physical pads, latch buffer, running mode), `voices`, `name`, `chain_params` and `ui_hierarchy` (served from `module_meta.h`, chain_params with the current mode's macro names), `is_loading` (see Screen), and the read-only readouts `pitch`, `target` (Hz) and `cents`.
- `state` is a flat JSON object `{"mode":"Snap","key":"C",...}` (every param except Freeze and Demo). The loader applies recognised members, ignores unknown keys and nested values, and rejects non-objects. `create_instance` applies `config_json` through the same path.
- `viz` (text): pitch modes `c,<f0_hz>,<target_hz>,<cents>`; Robot `d,<b0>..<b15>` (0–255 on a 60 dB scale).
- **The library must be named `<id>.so`** and `module.json`'s `dsp` must match. The chain module builds `…/modules/audio_fx/<id>/<id>.so` (verified from its strings and from every working FX on the device: `gate.so`, `tapedelay.so`, …). A file called `dsp.so` makes the module appear in the browser but fail to load. (The upstream docs say `dsp.so`; the device is authoritative.)
- Host headers: `plugin_api_v1.h`, `audio_fx_api_v2.h` from `charlesvestal/schwung` (`src/host/`). Pin with `SCHWUNG_REF`.

## Toolchain

Zig is the C compiler. **Target is glibc, not musl**: Move's host `dlopen`s the module into a glibc 2.35 process, and a musl `.so` would drag a second libc in.

    -std=c11 -Wall -Wextra -Werror -pedantic \
    -Isrc/host -Isrc/dsp \

## Engine notes

- **Tracker (`cher.c`)**: the analysis path only is high-passed (2 x 1st order, 50 Hz; DC/rumble otherwise stops MPM finding any pitch) and boosted +12 dB. 2x-decimated, window 768, hop 256, 70-1000 Hz, clarity >= 0.65 (Snap: from char2), median of 3, holds 6 hops (~35 ms). Quantizer has 10-cent stickiness (it never holds a note the current scale doesn't allow) and applies Key as the scale's root (`note_allowed`: (note - root) mod 12 against the scale mask; tested over all 12 keys); in Chromatic, Key changes nothing by definition. It runs every analysis hop (~11.6 ms), so a Scale change is heard within a couple of blocks (tested: a sung C#4 goes to C4 on Major, back on Chromatic). Scale is ignored while a pad, or Demo's Believe pad, sets the note, and only notes outside the new scale change. **Decided (2026-10-09): pads stay chromatic and are never constrained by Key/Scale**; a pad press plays the exact note pressed (only the octave fold beyond +-12 st applies). **Pad octave fold** (`cher_fold_octave`/`cher_fold_chord`): within +-12 st of the voice (measured from its nearest semitone) a pad plays at its own octave, so octave jumps on the pads are heard; further away it folds by octaves only until it is back inside +-12 (A5 over a sung A3 -> A4, A1 -> A2; C1 -> C3 while C4 stays C4). A chord folds as a block by its mean. Callers pass `same` (the pad or pad set is unchanged since the last block): only then is the previous fold kept within a semitone either side of the edge, so a voice moving near +-12 doesn't flip it, while a new pad always gets the plain rule and an octave jump is never swallowed. Move's pads sit around E5-G5, beyond the shifter's +-1 octave, which is why folding exists (seen on the device). In Chords/Prism the register fit (+11 / -12, below) still applies afterwards, so there a pad exactly an octave above the voice lands at unison; octave-down pads keep their octave. Robot folds its own way (into a fixed carrier register, see MIDI above), not around the voice. Lead retune/glide via `cher_lead_lr()`; glide is an offset from the target note (absolute float32 slews stall short).
- **PSOLA (`psola.c`)**: grains are 2 input periods, Hann, emitted every T0/pitch_ratio and read at formant_ratio speed; marks step by whole periods on a grid chosen so x1 is an exact delayed copy (latency about half a period + |span - len|/2; the dry path uses `lat - 1`). Epoch snapping to waveform peaks was tried and made things worse on formant-dominated voices (the peak hops between partials); the MPM period alone keeps the grid coherent (>= 0.999 autocorrelation at the target period, x0.5..x2). Level varies a few dB with ratio. Ratios clamp to x0.5..x2 (+-1 octave), span <= 3000 samples. Unvoiced: fixed 256-sample period at x1.
- **Snap "Believe" character** (`modes.c` Snap case, `psola_kick`/`psola_set_tight`): Retune 0 is a 4.5 ms snap (`RETUNE_MIN_MS`; it was an instant ratio step, part of the clicks reported on the device; 10 ms was too soft). Every target-note change (pad or quantizer) at Retune 0 triggers a phase reset at the next grain: the epoch grid re-anchors and sounding grains fade out early over a smooth taper of at least 5 ms, so old and new phase briefly overlap. (It used to cut over half a period and start the new grain halfway up its window: both hard edges, i.e. clicks.) Reset strength fades to none by Retune 50 ms; a held note never resets. The formant follows `couple * lr` (0.25 at char1 <= 0.5 rising to 1.0 at 1), on top of the char1 offset; above 0.5 grains shorten from 2 to 1.2 periods (`tight`, about -1.3 dB, still periodic). Other modes run `tight = 0` and never kick. Measured: a pad jump A3 -> D4 is within 30 ct by ~35 ms (the test's window; the 4.5 ms snap gets there sooner); up/down 7 st brightness skew x1.17 (char1 0.5), x1.84 (0.75).
- **Snap "space-age" voicing (2026-10-09)**, Snap only (`modes.c`, `SNAP_*` in `modes.h`): (1) the formant sits +2.5 st up (`SNAP_FORMANT_LIFT`, added to char1's offset; also on unvoiced sound), centroid of a held A3 vowel 698 -> 816 Hz; (2) `fx_snap_voicing`: 4th-order Butterworth 350 Hz high-pass and 5 kHz low-pass (TPT SVF pairs, Q 0.541 / 1.307), a +4 dB bell at 2.5 kHz (Q 1.2), makeup x1.66 (+4.4 dB, what the band took off the Demo phrase; Demo through Snap is now in = out). Measured response: 100 Hz -39, 1 kHz +5, 2.5 kHz +8, 10 kHz -25 dB; a D3 voice's fundamental is -28 dB of the output in Snap vs -2 / -4 dB in Morph / Double. It runs after Beauty's de-harsh and shelf (so the 12 kHz air shelf is now mostly cut by the 5 kHz low-pass) and before its micro-double; the filter states are cleared in other modes. (3) **Beauty 0 = instant retune**: Snap with Beauty <= 0.005 passes retune -1 to the tracker (`cher_lead_lr`: no slew at all, not even the 4.5 ms floor) and Glide 0, whatever Retune and Glide say: a sine 46 ct under A#3 is on A#3 at once (0 ct; Beauty 0.5 with Retune 500 is still 31 ct off). The Retune and Glide widgets still show their values there. A pad jump at the instant setting has no output step (tested, relative to the sine's slope). Tested: `test_snap_space_age`. Tuned on synthetic signals only; judge on a real voice.
- **Clicks (fixed 2026-10-09)**: the main cause was PSOLA reading past the write head: its latency only slewed toward a larger target when the pitch fell (longer grains), so grains read unwritten ring samples (~90 ms old): up to 195 samples ahead on 400 -> 120 Hz jumps, 4 on a smooth sweep, in Snap and Prism. Now the latency jumps up at once (slews down only), every grain is checked at birth and moved back by whole periods if any read would come within 2 samples of the newest one (`HEAD_MARGIN`), and the dry delay glides over ~3 ms across such a jump (`dry_follow`) instead of stepping. Grains are never shorter than 5 ms. The quantizer's stickiness is 20 ct (`HYST_SEMI`; a wobble of +-10 ct on a semitone edge holds).
- **Octave errors (fixed 2026-10-09)**: MPM takes the first strong peak, so a loud 2nd harmonic (a vowel with F1 on it) can win at half the period. Fundamental bias (`cher_mpm`): the peak at twice the pick's lag wins if it is at least `MPM_OCT_MARGIN` (0.085) higher. A "nearly as strong" rule (0.85-0.97 of the pick) drops clean notes an octave: at twice the period a clean note's peak is about as strong as at the period. Octave-glitch hold (`analyse`): a jump of an octave (+-50 ct) with no onset (already voiced, level within 6 dB) is held in the old octave until it lasts `OCT_CONFIRM` (3) hops; on confirmation the median-of-3 history moves with it (without that, the two held hops outvoted every real leap). Measured on synthetic rough voices: F1-on-H2 vowel 38 octave-up frames -> 0, octave leaps followed in ~35 ms (was ~30), strong creak (alternate cycles 40% quieter) read an octave down in 26% of frames (was 9%): the margin trades those two, above ~0.09 the H2 errors return. Tested: zero reads past the head over jumps of pitch, ratio and formant; no output step at a Retune-0 pad jump.
- **Chords (`imogen.c`)** and **Prism** share the harmony rules: every voice is a formant-preserving PSOLA voice (formant ratio 1; Chords used delay-line taps until the device showed chipmunk 3rds/5ths); after the targets are chosen, `vt_fit_register` keeps each voice within [sung note - 12, sung note + 11] by octaves (a 3rd/5th that would land higher drops an octave; the floor is PSOLA's +-1 octave, past which a voice would sound the wrong pitch); unvoiced sound (consonants, or a note the tracker lost) passes on voice 0 at ratio 1 through a 2-pole 2.5 kHz high-pass blended in over 10 ms, so it can't bleed as unshifted pitch at 100% wet (measured on noise: 200-800 Hz -20 dB or more, 5-8 kHz within 3 dB); the wet bus gets `VT_HARMONY_TRIM` (+1.5 dB; was +4.5, -3 dB for headroom), and Chords with Auto Off another +1 dB (`CHORDS_MANUAL_TRIM` in `dsp.c`; +2.5 dB net over the input; +9 dB drove hot voices into the output limiter; with Auto On the AGC sets the level). Every mode but Robot otherwise follows the raw mic level with Auto Off, while Robot's leveller always lands near -13 dBFS: that, not the harmony bus, is why other modes sound small next to Robot on a quiet mic. A ~-23 dBFS loop plays through Chords (Auto Off, Gate -40 dB) with no gating holes. Measured levels with that trim, Auto On: Chords -18, Prism -17, Morph -18, Snap -22, Robot -13 dBFS. Note a formant-preserving shift of a pure sine is weak far from the sine (no spectrum there to keep): test with harmonic tones. Voices fade 10 ms, glide per voice, equal-power pans.
- **Vocoder carrier and floor (2026-10-12, `daft.c`)**: (1) a note-on never resets the oscillator phases (they free-run: an idle voice holds its phase); a note given to a *sounding* voice with no Glide (a stolen slot, a changed chord) no longer jumps in pitch: the voice fades out over 0.5 ms (raised cosine), takes the new note at the bottom and fades in over 0.5 ms (`rt`, `rt_pos`, `pend_note`; a note landing mid-fade starts from the current gain); with Glide the pitch slides and there is no dip. (2) A 15 Hz DC blocker (`y = x - x1 + R y1`, R = 1 - 2 pi 15 / sr) after the carrier's oscillator stage (before the CARRIER_GAIN): the carrier's mean was already 0.4 % of its RMS, so this guards more than it fixes. (3) **Analysis floor** (`an_open`): when the raw input level (the same follower the Gate knob reads, which is about 1.43 x a sine's amplitude and rides noise peaks higher) is under -48 dBFS (0.00398) every band envelope and the consonant high-band follower are held at exactly 0, and it opens again only above -45 dBFS (0.00562): 3 dB of hysteresis. A manual Gate lower than that moves the floor down with it (`min(floor, gate_thr)`), so a quiet-voice setting still works; in Auto the floor is the constant. (4) The bands whose *synthesis* centre is above 3.5 kHz release their envelopes in 5 ms instead of 15 (`k_rel[i]`, set in `design_bank` so the Formant shift moves bands across the line). (5) The consonant-noise amount `sib` is forced to 0 the instant the gate shuts or the floor closes (it used to fade over its 2 ms smoother while the bands rang on): the bands' own ring-out then falls under the 3 ms gate fade, 3e-5 by 10 ms and exact digital zero by 50 ms (`test_vocoder_floor_and_release`, `test_vocoder_carrier`). (Robot is therefore no longer bit-identical to v0.9.)
- **Robot (`daft.c`)**: analysis and synthesis banks are separate; Formant moves only the synthesis centres. Band width fixed at 0.5 and carrier detune at 8 ct (their old knobs went to formant/ensemble). Stereo: odd bands left, even right, by Spread (a lone tone separates ~5 dB because neighbouring bands overlap). Ensemble: 3 BBD-like taps (7 ms +- 2 ms at 0.62 Hz, +- 0.3 ms at 6.1 Hz, 120 degrees apart), 7 kHz dark feed. Consonants: the detector high-passes at 2.5 kHz (it was 5 kHz, which missed 'k' bursts at 1.5-4 kHz) and needs both a hiss-dominated spectrum (hiss / (hiss + low bands) from 0.40, smoothstep to 0.8) and >= 15% of running speech energy; measured on synthetic speech: s 1.0, t 1.0, k 0.55, sustained vowels (bright, breathy, high "ee") 0. Consonants were re-checked for the built-in mic (2026-10-09): with 40 Hz hum and pad thumps under the speech, through the input high-pass, s / t / k scores are unchanged (tested). A separate > 4.5 kHz detector was requested and not added: the detector already injects level-matched noise (amount x hiss level, 2 ms smoothing) into the carrier, which the synthesis bands then shape, and a 4.5-5 kHz detector is the one that missed 'k'. Carrier gain 0.60, noise 1.8, makeup 5.66x, then an output leveller (RMS target 0.1416, peak ceiling 0.89, gain 1..5.6x, never cuts) before the tanh limiter above 0.8: the vocoder's ~17 dB crest factor meant static makeup only hit the limiter. Makeup and target were 8x / 0.20 until both came down 3 dB for headroom. Measured ~-16 dBFS RMS out for voice from -40 to -10 dBFS. **Phrase onsets**: the leveller and the input AGC's follower only update while the gate is open, so a pause holds the last phrase's gain (the silent output had let the leveller climb to full makeup and the AGC follower decay, and every phrase after a pause of 1 s or more opened 5-8 dB hot into the limiter for ~20 ms); a cold AGC follower starts at unity gain and settles at 1 ms both ways over the first 20 ms of voice (from zero it gave +30 dB: a burst on the first switch to Robot). Now within -3..+3.4 dB of steady (tested < +4.5 dB, Auto On and Off, cold included). When its gate is fully shut (its own, or Auto's via `daft_set_voice_present`) the output is exact zeros and the band envelopes, consonant amount and ensemble line are cleared, so pauses are digital silence (tested, Auto On and Off).
- **Beauty** (`beauty`, 0-1, default 0.5): per-mode polish, scaled by the knob. Robot (`daft_set_beauty`, `daft_set_params`, `daft_set_stereo`): carrier detune 0..+-7.5 ct (0.5 is about the old fixed +-4), a sub-octave sine per carrier voice (up to -10 dB), the carrier blended toward an 11 kHz low-pass, the voice's own air above 5.5 kHz bled in through the gate, band spread +35%. ## Screen (OLED)

How Schwung draws module data, verified from the shadow UI source on the device:

- A module's `ui_chain.js` is loaded **only if the component serves no `ui_hierarchy`** (the hierarchy editor wins), and it would replace the stock pages. So TinyVoice has **no** `ui_chain.js`.
- Instead, `chain_params` entries can declare `"viz": {"kind": "custom:<name>", "group": ..., "role": ..., "extra_keys": [...]}`. The host then loads `<module>/canvas.js`, which sets `globalThis.canvas_overlay = { widgetKinds: { "custom:<name>": { draw, nominal } } }`. Members of one group in adjacent cells of one row become a single picture across them. `draw(ctx, {values, nowMs, group})` gets a clipped frame (`width/height/fillRect/print/textWidth/setPixel/line`); `values` holds the page's params and the `extra_keys`, read by the host one key per tick on its rotation (~5 Hz each), never on the draw path. Draw budget ~1.68 ms per page; a throw disables the widget for the session and the stock dials come back.
- **The module must answer `get_param("chain_params")` itself** (and does, plus `ui_hierarchy`, from `module_meta.h`). The chain host's fallback re-serialises chain_params from its parsed table and drops `viz`, so without this the widget never mounts and the stock dials show (seen on the device). tinyk, hank and monksynth all serve theirs.
- TinyVoice declares `custom:tinyvoice_scope` on PITCH knobs 5-7, which hold three read-only readouts (`pitch`, `target`, `cents`; `"access": "read"` makes a cell a readout the knob can't change), fed by the `scope` key (`format_scope` in `dsp.c`, built only when read): pitch modes show target note + cents needle, Robot its 16 analysis bands, and Freeze a loop playhead line (looping) or a bar filling with the buffer and a blinking head (recording; the feed's freeze field is 0 live, 1 looping, 2 recording), Auto a "+NN" input-boost readout, and pads an inverted target label plus a dot that flashes per note-on (shows whether pad MIDI reaches the FX). The widget eases between reads and runs the playhead on locally.
- `visible_if` (param or level): `{"param": "<key>", "equals"|"not_equals"|"gt"|"lt"|"truthy": ...}`, compared against the param's `get_param` string; one condition, no AND/OR; fails open if unreadable. TinyVoice uses none any more (tested): Gate used to hide while Auto was On, which read as a disappearing control; Gate now holds Auto as its lowest setting.
- `custom:tinyvoice_latch` (MORE knob 2, one cell, `extra_keys: ["mode"]`): reads `values.mode` and `values.latch` (names or indices) and draws the value itself, so it can say "---" where an enum knob's value text can't (the host's knob turning looks the value up in the options). Dimmed = every other pixel cleared with `setPixel` over the text. Unknown mode: shows the value. Tested over 7 modes x values x 24-40 px cells, same position everywhere.
- Visible params are re-read on the same rotation, so a value the DSP changes itself (Demo stepping `mode`) shows up within ~0.2 s with no encoder movement. Nothing extra to export.
- **Per-mode knob names.** A knob's value text is the host's: raw number + `unit`/`display_format` (`shared/param_format.mjs`), no per-mode scaling, so "+3 st" on a 0..1 knob is not possible, and a non-numeric `get_param` value breaks knob turning (`parseFloat`). Names are the module's: the cell label is `chain_params` `name`. The DSP serves chain_params with char1/char2/mod named for the current mode, and pulses `is_loading` "1" for 0.6 s after a mode change (knob, state or Demo). The knob pages poll `is_loading` every 8 ticks and re-read chain_params on its fall to "0" (`shadow_ui_param_pages.mjs` -> `controller.reloadIfChanged`; the hierarchy editor does the same). No pulse in the first second after load: the host's set restore busy-waits (up to 10 s) while `is_loading` reads "1". Unverified on the device.
- Widget registration is logged as `widgets: tinyvoice registered custom:tinyvoice_scope` in `debug.log` (verbose logging only, i.e. with `debug_log_on`).
- **Widget resolution is latched per shadow-UI process.** If the UI first saw TinyVoice without a widget (e.g. an older build that didn't serve chain_params), it keeps showing stock dials after a reinstall until Schwung restarts (`restart-move.sh`). Confirmed on the device: after a restart the widget mounted.

## Device notes (Move, BusyBox + glibc 2.35)

- Shell tools are BusyBox: no `ldd`/`curl`/`journalctl`, `head -N` is invalid (use `head -n N`). Check linking with `LD_TRACE_LOADED_OBJECTS=1 /lib/ld-linux-aarch64.so.1 <so>`.
- Logs are in `/data/UserData/schwung/` (`debug.log`, `schwung.log`, `schwung-manager.log`); FX load failures are not obviously logged there. Use `smoke_on_device.sh` to separate library faults from metadata/path faults.
- **Reading a live instance**: `bin/schwung-testd` (Schwung's test daemon, not running by default) listens on 127.0.0.1:47777 with a line protocol: `SLOT 3` (0-based), `GET_PARAM fx1:<key>`, `SET_PARAM fx1:<key> <value>`, `STATE` (includes `speaker_active`, `line_in_connected`), `INJECT_MIDI <8 hex>` (a USB-MIDI packet as hardware: presses a real pad). BusyBox `nc` has no `-w`: `(printf 'SLOT 3
GET_PARAM fx1:diag
'; sleep 1) | nc 127.0.0.1 47777`. Start it, query, kill it.
- **Measured on the device (2026-10-09, built-in mic via Line In, trim 0, speakers off)**: room with nobody singing, 10 ms RMS floor -45..-54 dBFS, peaks -29..-40 dBFS each second, so the default Gate (-38) opens 5-35% of the time on the room alone, and Robot (leveller up to 5.6x) played it at up to -9 dBFS. A realistic voice through Robot computes identically on the device and natively (same numbers from a cross-compiled probe).
- Debug switches are empty flag files in `/data/UserData/schwung/`, read at process (or chain) start: `debug_log_on` (verbose `debug.log`, grows fast), `chain_debug_on`, `chain_midi_trace_on` (logs `chain_trace IN <status> <d1> <d2>` per slot to `chain_debug.log`). Remove them when done.
- Display is 128×64. `clear_screen`, `print`, `fill_rect`, `host_module_get_param/set_param` exist for UI scripts (see other modules' `ui_chain.js`).
